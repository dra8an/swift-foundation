## Two new commits on `origin/port/hebrew-main` since the last HANDOFF

Both authored by Tina Liu (upstream reviewer) on 2026-05-20 — these are the
final pre-merge fixes that addressed cross-platform / cross-target issues:

### `f94c6ac` Fix missing `floor` and add a feature flag

- `Sources/FoundationEssentials/Calendar/Calendar_Cache.swift` (+13/-1)
  - Adds `foundation_swift_hebrew_calendar_feature_enabled()` (binds to
    `_foundation_swift_hebrew_calendar_feature_enabled` via
    `_ForSwiftFoundation` when `FOUNDATION_FRAMEWORK`; returns `false`
    otherwise).
  - Hebrew router gated:
    `else if foundation_swift_hebrew_calendar_feature_enabled() && identifier == .hebrew { return _CalendarHebrew.self }`.
- `Sources/FoundationEssentials/Calendar/Calendar_Hebrew.swift` (+10)
  - Adds platform-specific libc imports for `floor()`:
    `Bionic` / `Glibc` / `Musl` / `CRT` / `WASILibc` (in addition to the
    existing `os` import on Darwin). Without these, Linux/Android/Windows
    builds failed to find `floor`. This was a confirmed root cause of the
    `#2015` revert.

### `b1b8fdf` Move ICU-dependent Hebrew calendar tests to FoundationInternationalizationTests

- `Tests/FoundationEssentialsTests/HebrewCalendarTests.swift` (-94)
- `Tests/FoundationInternationalizationTests/HebrewCalendarICUTests.swift` (+108)
- Three tests that constructed `Calendar(identifier: .hebrew)` were
  SIGSEGV-ing in `FoundationEssentialsTests` because that target doesn't
  link `FoundationInternationalization`, so `_calendarICUClass()` returns
  nil. Moved them to a new file in `FoundationInternationalizationTests`
  where the ICU backing is available.
- Tests moved (per commit body): all three that referenced
  `Calendar(identifier: .hebrew)`.

These were also part of the squash that landed via #1953 and re-landed via
#2017, so the upstream `Calendar_Hebrew.swift` content matches
`port/hebrew-main`'s tip.
